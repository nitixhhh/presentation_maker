# Academic and student decks (school, college, university)

Most DeckCraft users are students in Indian colleges and universities presenting seminars, projects,
assignments and practical reports. Teachers grade clarity, structure, correct sources and the
title slide details.

## Title slide fields — use ONLY what was given
Typical fields (the engine passes the ones the student filled, as placeholders {{P1}}, {{P2}}…):
- Topic / title of the presentation (and subject or course name, subject code if given)
- Presented by / Submitted by: student name(s)
- Roll No. / Enrollment No. / Registration No. / Student ID
- Course / branch / programme, semester or year (e.g. "B.Tech CSE, 5th Semester")
- Department, Institute / College / University (logo if uploaded — see images.md)
- Submitted to / Under the guidance of: teacher's name and designation
- Session or date
Rules: never invent a value, never add a field that was not given, never write "Your Name", never
guess a semester or a professor. Write each placeholder exactly. Layout: title dominant; details
as a neat label–value block (labels muted 18–20 px, values 20–24 px), aligned on one grid.
For group projects, list members in a 2-column grid when there are more than 3.

## Common deck structures
Seminar / topic presentation (8–12 slides):
Title → Agenda → Introduction (what & why) → Background/history → Core concept(s) → How it works
(diagram) → Applications/examples → Advantages & limitations → Current research / future scope →
Conclusion → References → Thank you.

Project / research presentation:
Title → Introduction & problem statement → Objectives → Literature review → Methodology (process
diagram) → System design / architecture (layers or flow) → Implementation → Results (charts/tables)
→ Discussion → Conclusion & future work → References → Thank you.

Lab / practical report: Aim → Apparatus → Principle/theory → Procedure (steps) → Observations
(table) → Result → Precautions → References.

Map each to a layout: objectives → icon cards; literature review → table (author, year, method,
finding); methodology → process; results → chart or stats; future scope → icon cards.

## Tone and content
- Clear, factual, exam-friendly wording; define technical terms on first use.
- Every non-obvious fact or number has a citation marker `<sup>[n]</sup>`.
- No marketing language ("revolutionary", "game-changing") unless quoting a source.
- Slide count usually 10–15 for a 10–15 minute talk (about one slide per minute).
- Speaker notes: what the student should say, in simple spoken sentences, in the deck's language.

## References (APA-style, 7th edition shape)
The engine builds the reference list from real sources; the designer never edits it. The shapes:
- Journal article: Author, A. A., & Author, B. B. (2021). Title of the article in sentence case.
  Journal Name, 12(3), 45–67. https://doi.org/10.xxxx/xxxx
- Book: Author, A. A. (2019). Title of the book (2nd ed.). Publisher.
- Web page: Organisation or Author. (2024, March 5). Title of the page. Site Name. URL
- Wikipedia: Title of article. (2026, Month Day). In Wikipedia. URL
- Image credit: Title — Author — Licence (e.g. CC BY-SA 4.0) — Source (e.g. Wikimedia Commons)
Many Indian engineering departments ask for IEEE style instead ([1] A. Author, "Title," Journal,
vol. 3, no. 2, pp. 10–20, 2021.) — follow the brief's citation style if it names one.
In-text: numbered markers [1], [2] in order of first use, matching the reference numbers.

## Indian university norms worth knowing
- Logo of the university/college on the title slide is expected; not on every slide.
- "Submitted to / Submitted by" or "Guided by" blocks are common on the title slide.
- A "Thank You" final slide is standard; "Any questions?" is optional.
- Hindi or Hinglish decks are acceptable when the brief says so; keep technical terms in English.
- Teachers penalise copied text and missing references more than plain design: always cite.

## Don't
- Don't invent references, authors, years, DOIs or URLs.
- Don't put the full reference text on content slides — just the marker.
- Don't fill the title slide with decorative text like "A presentation on…" if a title was given.
